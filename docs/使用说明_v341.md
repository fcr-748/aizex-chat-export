# 使用说明 v3.41（"只剩零头"的真正原因：接口的父链是断的）

脚本文件：[src/aizex_export_v341.js](../src/aizex_export_v341.js)

## 一、证据

拿 9/26 那份归档当基准逐条对比，缩水的就 5 条（其余 266 条还没重跑，所以没变）：

```
哲学论文          898KB → 29KB   (3%)
常微分课程答疑     150KB → 13KB   (9%)
财政学探索        267KB → 35KB   (13%)
偏导数两种求法     205KB → 42KB   (21%)
生涯ai辅助         35KB →  8KB   (23%)
```

再看文件头新加的「抓取情况」（这行就是为此加的）：

```
> 抓取情况: 接口 12 条；页面 5 条；最终 12 条；面板标 0 轮；取源 api
```

《哲学论文》接口只回来 **12 条**——同一会话在 9 月那次抓取里接口给过 **445 条**。两边都薄，文件自然只剩零头。

## 二、两个原因

### 1. 接口的父链是断的（主因）

会话数据是一张消息节点图，每条消息记着自己的 `parent`。上一版为了取"页面上当前显示的那条"，从 `current_node` 顺着 `parent` 往上走——但**这套镜像的链经常是断的**，走几步就到底了，于是 445 条的会话只回来 12 条。

现在两条路都走：

| 取法 | 说明 |
| --- | --- |
| 顺链（`current_node` 往上） | 正常情况下用这个，能避开"重新生成"留下的分叉 |
| 整张图按时间排 | 链明显比全节点短（不足 80%）时改用这个 |

文件头的「抓取情况」会标出来：`取源 api(全节点)`，并给出 `链 12/全 445` 这样的对照。

### 2. 页面只圈到一个很小的子树

`[data-testid="conversation"]` 这个容器选择器有时候只匹配到一小块（实测"页面 2~5 条"），于是**公式原文来源、图片兜底地址全都没了**——这也正是你上一条"图片还是没呈现好"的原因。

现在容器和全文档都查一遍，**取更全的那份**。

## 三、修复后的预期

- 长会话的接口条数应该回到几百条的量级（对齐面板显示）
- 页面条数不再只有个位数 → 公式按接口原文、图片有页面地址兜底
- 文件头能直接看出账：`接口 N 条；页面 M 条；最终 K 条 … 取源 api(全节点)；链 12/全 445`
