# 使用说明 v3.43（能不能在 VS Code 预览里看到图片）

脚本文件：[src/aizex_export_v343.js](../src/aizex_export_v343.js)

## 一、分两层说清楚

**第一层：引用方式（这一层没问题）**

图片写成相对路径 `![图片](images/xxxx.png)`，`.md` 和 `images/` 在同一层目录里，VS Code 内置预览会直接渲染。

全归档实测：

```
md 文件数: 475
图片引用总数: 67；文件存在: 67；缺失: 0
```

也就是说：**只要图片下到了本地，预览里就能看到**。这和你之前"文末那些图能显示"是同一套机制。

**第二层：图片能不能下到（取决于面板）**

镜像站的文件端点各家不同，脚本会按顺序试：

1. 页面上渲染出来的地址（浏览器正在用的那个，最可靠）
2. `/backend-api/files/<id>/download`（拿 JSON 里的 download_url 再拉一次）
3. `/backend-api/files/<id>`、`/raw`、`/content`

三条都不通时（v3.43 起）：正文写成**可点链接**——

```
［图片未取到］[点这里打开原图](https://…)

> 附件: `file-xxxx`
```

点开就是原图（走你自己浏览器里的登录态）；文末附录还会列出"试过的地址 + 状态码"，方便我按真实端点继续补。

## 二、v3.42 + v3.43 合起来解决了什么

| 版本 | 修的 |
| --- | --- |
| v3.41 | 接口父链断了 → 长会话只剩零头（按全部节点取） |
| v3.42 | 界面图标过滤误伤真图（消息里的图不再按按钮过滤）→ **图片恢复能下载** |
| v3.43 | 万一还下不到：给可点原图链接，而不是含糊的提示 |

## 三、格式标记仍是 md-v11

你手上那批是 md-v10，重跑一趟会一起覆盖。跑完检查两点：正文里是不是 `![图片](images/…）` 直接显示；文件头的「附件」那行有没有写"没取到"。
