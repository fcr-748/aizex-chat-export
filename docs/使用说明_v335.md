# 使用说明 v3.35（扫清单不再傻等：接口列全就不滚侧边栏）

脚本文件：[src/aizex_export_v335.js](../src/aizex_export_v335.js)

## 一、先回答"每轮是不是都扫一遍"

是，每轮都会把面板上的会话清单走一遍，但**扫清单**和**抓内容**是两件事：

| 步骤 | 做什么 | 代价 |
| --- | --- | --- |
| 扫清单 | 拿到所有会话的 ID + 标题 + 更新时间 | 接口一次列全：5 个请求左右 |
| 逐条判断 | 新对话 / 有更新 / 旧格式 → 抓；其余 → 跳过 | 几乎不花时间 |
| 抓内容 | 只有要抓的才会打开会话、展开折叠、下载图片 | 每条几十秒 |

所以"没有新对话就下一个"是对的——跳过的那些根本不会打开页面。

## 二、这一版把最慢的一步省掉了

以前无论接口有没有列全，都要再去滚侧边栏把同一份清单加载一遍：先拿 14 个候选容器逐个试（每个 1.5 秒），再最多滚 150 轮，**实测能占掉好几分钟**。

现在：

- 接口列全（≥20 条，且不少于页面上已有的）→ **直接跳过滚动**，清单用接口的
- 只有这一轮"要抓的条数 > 20"时，才会补滚一次侧边栏（抓的时候要靠它定位会话链接）
- 只抓几条的时候不滚：需要打开哪条，脚本自己会滚到那条去找

`_诊断_导出.md` 的"侧边栏收集"里多了两个字段，能看出来这次走的是哪条路：

```
侧边栏收集: {"found":493,"inDom":38,"source":"api","scrollSkipped":true}
```

## 三、格式没变

格式标记仍是 `md-v7`，这一版只改"扫清单"的做法，**已有文件不需要重导**，下次运行就能感受到速度差别。
