# 使用说明 v3.40（开头那一段补到开头；面板界面文字不再混入）

脚本文件：[src/aizex_export_v340.js](../src/aizex_export_v340.js)

## 一、《大学生失业讨论总结》到底缺在哪

先纠正我上一轮的判断：那 22 条**不是没抓到**，而是抓到了却放错了地方。文件里是这样的：

```
1030: ## 附：另一来源里独有的消息（共 22 条，只有页面版）
```

也就是说：接口那份缺了**开头一段**，页面版有这 22 条，但上一版的"按位置合并"只比较"头尾对不对齐"——接口缺的是开头整段，一比就对不上，于是整片退回附录（文末），看起来就像被掐断。

## 二、这一版的合并规则

改成**逐条判断 + 看位置**：

1. 先逐条判断这条消息在正文里有没有（按内容指纹，或用包含关系）
2. 再看它在页面版里排在哪儿：

| 位置 | 去哪 |
| --- | --- |
| 排在第一条"正文里已有"的消息**之前** | **补到开头** `## 补：更早的消息（页面版，接口没返回）` |
| 排在最后一条已有消息**之后** | 接到正文后面 |
| 夹在中间 / 一条都对不上 | 才进文末附录 |

《大学生失业讨论总结》那 22 条属于第一类，以后会出现在正文开头。

## 三、面板界面文字不再当消息

上一份文件结尾混进了面板自己的提示（`Response ready`、`You've reached your quota`、`Start typing a prompt to see...`、Google 搜索建议等）。现在这些短提示会被过滤掉，不再写成 AI 消息。

## 四、文件头多一行"抓取情况"

以后哪条抓得对不对，看文件头就知道，不用翻诊断：

```
> 抓取情况: 接口 74 条；页面 43 条；最终 97 条；开头补 22 条；面板标 7 轮；点展开 18 次；残留折叠 0；取源 api
```

- `开头补 N 条` = 接口没给、从页面版补到开头的条数
- `点展开 C 次` / `残留折叠 B` = 折叠展开点了多少次、还剩几个没展开
- 这行也是排查问题的第一手证据
