# 使用说明 v3.32（更新时间台账 + 有更新就重抓）

脚本文件：[src/aizex_export_v332.js](../src/aizex_export_v332.js)

## 一、想解决的问题

面板上有些会话是**一直在补写**的（今天聊完明天接着聊）。希望每次运行：

1. 新会话照常抓
2. **已经抓过、但面板上有内容更新的，也自动重抓**
3. 没更新的继续跳过，不用全量重跑
4. 每条的更新时间都记下来

## 二、怎么判断"有更新"

接口 `/backend-api/conversations` 每条会话都带 `update_time`（面板自己的更新时间）。脚本把每条的时间记进 `_同步台账.json`，下次运行时：

| 情况 | 处理 |
| --- | --- |
| 面板时间和台账里一致、文件格式已是最新 | 跳过 |
| 面板时间比台账里新 | **重抓**（并在诊断里列出标题 / 新时间 / 旧时间） |
| 台账里没有这条 | 重抓 |
| 文件格式不是最新（旧版本写的） | 重抓一次（格式升级） |

## 三、台账这次做实了

以前只有"本次导出的"会话才进台账，而且**只在跑完时才写**——跑一半停掉等于没记。现在：

- 开跑后先给面板上**每一条**会话记一次更新时间快照（不只是要抓的）
- 之后每 5 条再写一次盘，中途停掉也不丢
- 台账语义写清楚了：记的是"磁盘上这份内容对应的面板更新时间"。已经记过时间、这轮没抓到、面板时间又变了的，台账**不动**——那是"有更新还没抓"，留给下次继续，不会被误当成已处理

## 四、更新时间在哪里能看到

| 位置 | 内容 |
| --- | --- |
| 每条 `.md` 文件头 | `> 最后更新: 2026-09-18 15:52` |
| `00_索引.md` | 每条后面 `　最后更新 …`（文件自己带的优先，没带的取台账快照，所以不用等全部重抓完就能看到） |
| `manifest.json` | 每条多一个 `updated` 字段 |
| `_同步台账.json` | 每条的 `updateEpoch`（原始值）+ `updatedAt`（可读时间）+ 上次导出信息 |
| `_诊断_导出.md` | 新增一节「面板上有更新的会话（本次重抓）」表格 |
| 面板状态栏 | "面板上有更新、本次会重抓 N 条: …"，收尾会写"其中面板上有更新的 N 条已重抓" |

## 五、怎么用

保持**勾选**"跳过已抓过的会话"，正常点开始即可：

- 第一次把旧格式补完（这一趟要跑全）
- 之后每次运行只会抓"新会话 + 面板上有更新的会话"

接口没返回 `update_time` 时，状态栏会明说"这次拿不到更新时间，只能按已有文件跳过"，避免误以为在增量。
