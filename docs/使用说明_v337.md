# 使用说明 v3.37（第二种图片指针：sediment://）

脚本文件：[src/aizex_export_v337.js](../src/aizex_export_v337.js)

## 一、为什么图片显示不出来

面板里的图片指针有**两种写法**，我以前只认第一种：

| 写法 | 出现在哪 |
| --- | --- |
| `file-service://file-xxxx` | 直接上传的图 |
| `sediment://file-xxxx` | 从文档 / 图片里派生出来的图（比如整页扫描、图里再截图） |

只认第一种的后果：第二种在正文里只剩一个空的 `［图片］` 占位——没有 id、没法下载、也没法点击，看起来就是"图片没了"。

实测：你那份《概率论》里有 4 处这样的图，全都成了空占位；整个归档里有 56 个文件带 `sediment://`。

## 二、这一版改了什么

- 正文里的占位、页面/接口的指针收集、文件名的推导，三处统一按"任意 scheme"处理：
  `［图片:file-xxxx］`（两种来源都一样），下载时把 scheme 去掉再拼接口路径
- 下载失败的图不再"静默消失"：正文里会写
  `> 附件: \`file-xxxx\`（未下载成功，可在面板里查看）`

## 三、仍然可能下载不到的情况

面板的镜像站对文件端点各有各的写法，脚本会依次尝试
`/backend-api/files/<id>/download`、`/backend-api/files/<id>`、`/raw`、`/content`。
都不通时，占位和 id 会留在正文里——至少你知道那条消息原本有张图、id 是多少，去面板里能对上。

## 四、格式标记仍是 md-v8

这一版和上一版（界面图标过滤）合起来需要重导一次；`md-v8` 是同一个标记，所以只要跑一趟就都覆盖了。
