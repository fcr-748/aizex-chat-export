# 使用说明 v3.33（附件就地标注，图片回到它原来的位置）

脚本文件：[src/aizex_export_v333.js](../src/aizex_export_v333.js)

## 一、改动

以前不管会话里有几张图，都堆在文件末尾的「附：本会话涉及的图片」里，看不出哪张图配哪个问题。现在**图片就放在它出现的那条消息里**：

```markdown
## 用户

![图片](images/file-ABC.png)

> 附件: `file-ABC`

请解释：为什么元素总数为2n 元素和样本点是一个意思么？

## AI

这里最容易混淆的是：$\Omega$ 的元素和 $\mathcal F$ 的元素不是同一种东西。
```

图片是块级元素，前后各留一个空行，所以不会把后面的正文粘到标注那一行上。

## 二、附件身份

占位符现在带着身份信息，写文件时才能就地换成真链接：

| 占位符 | 含义 |
| --- | --- |
| `［图片:file-abc123］` | 图片（面板里的文件 ID） |
| `［文件:报告.pdf:file-abc123］` | 带文件名的附件 |
| `［文件:报告.pdf］` | 只有文件名、拿不到 ID |

接口的结构化附件、页面里那坨 JSON，两条来源都会产出这种记号。

## 三、文末附录什么时候还出现

只在"**正文里没定位到**"的时候出现，比如从页面上顺手捞到的签名图片地址（它不属于任何一条消息）。标题会写清楚：

```
## 附：本会话涉及的图片（正文里没定位到的 N 个）
```

正常情况（图片都来自提问里的附件）这节不会出现。

## 四、下载不到的情况

下载不到时原地写：

```
> 附件: `概率论基础.pdf`（未下载成功，可在面板里查看）
```

——保持位置，不丢信息。

## 五、文件头多一行

```
> 附件: 2 个（已就地标在对应消息里）
```

## 六、格式标记升到 md-v7

附件位置变了，所以升级后第一次运行会重导一遍（只这一次），之后恢复按 `update_time` 的增量。
