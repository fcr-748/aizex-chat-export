# 使用说明 v3.28（控制台脚本，当前推荐版本）

脚本文件：[src/aizex_export_v328.js](../src/aizex_export_v328.js)

## 一、公式为什么要靠接口

面板的公式是 KaTeX 渲染的，但**只输出 HTML，没有 mathml / annotation 层**。实测诊断里写得很清楚：

```
格式自检: 数学节点 3897 个（取到原始 TeX 0 个）
数学节点样本: <span class="katex-display"><span class="katex"><span class="katex-html" aria-hidden="true">…
```

也就是说页面 DOM 里只有"排版结果"（`Vλi={x∈Pn:Ax=λix}` 这种），**没有可以还原成 LaTeX 的东西**。公式原文只存在于面板后端接口返回的原始 Markdown 里。

所以取源规则在 v3.28 改了：

- **接口那份是原文，能用就用它**（公式是 `\(…\)` / `$$…$$` 原文）
- 页面那份只用来补接口没有的消息（附在文末"另一来源里独有的消息"）
- 只有接口明显残缺（比如只回了两三条）时才退回页面版

### 仍然做不到的部分

接口取不到的那条会话，页面里就只有排版结果。要把它反推成 LaTeX，只能按 KaTeX 的 class 结构（`mfrac` / `msupsub` / `sqrt` …）自己重新拼一套。脚本会把真实节点存一份到 `_数学节点样本.html`，用来做这件事。

## 二、图片 JSON 残渣

v3.27 只清理了页面那条路，接口正文没走，于是导出文件里出现：

```
［图片］
,"size_bytes":327298,"width":1005}请解释：为什么元素总数为2n …
```

v3.28 把三条来源（接口 / 页面 / 流式）的正文统一过一遍清理，整块 JSON 和"被拆散后的半截"都会清掉，图片指针照旧收集到文末清单。

## 三、公式定界符改成预览器认的写法

ChatGPT 里公式写成 `\[ … \]`（独立行）和 `\( … \)`（行内）。**绝大多数 Markdown 预览器不把这两种当公式**，而是当成"转义字符"，于是预览出来是这样：

```
[ \boxed{M(x,y),dx+N(x,y),dy=0} ]
```

注意 `\[` 变成了 `[`、`\,` 变成了 `,` —— 公式看着就散了。文件里的 LaTeX 本身其实是完整的。

v3.28 输出时统一换成通行写法：

| 原来 | 现在 |
| --- | --- |
| `\[ … \]` | `$$`（独占一行）+ 公式体 + `$$` |
| `\( … \)` | `$ 公式 $` |

Obsidian / Typora / VS Code / GitHub 都认这两种，预览就是真公式。代码块 ``` ``` ``` 和行内代码 `` ` `` 里的内容一个字都不动。

## 四、格式标记升到 md-v4

因为取源规则变了，旧文件要按新规则重导一次。所以**升级到 v3.28 后第一次运行会重导全部会话**（只这一次），之后恢复按 `update_time` 的增量。

## 五、怎么跑

1. 登录面板，进入聊天页（左侧能看到会话列表）
2. `F12` → Console → 粘贴脚本 → 回车
3. 右上角浮窗：本地桥接在跑就直接写；否则选**上次同一个**导出文件夹
4. 保持"跳过已抓过的会话"勾选，点开始

跑完看这几处：

- `_诊断_导出.md`：`取源规则` 那行、每条的 `抓取源`（api / dom）、`格式自检` 那行
- `_同步台账.json`：有没有正常长出来（下次增量靠它）
- `_数学节点样本.html`：有没有存到公式 HTML（有了就能研究反推 LaTeX）
