# 使用说明 v3.44（图片下载的真正卡点：200 被当垃圾扔了）

脚本文件：[src/aizex_export_v344.js](../src/aizex_export_v344.js)

## 一、证据就在文件里

v3.42 加的那行"试过的地址"直接把问题指出来了：

```
- ［图片未取到］`file-jNgKsM6YtMBIHm5BSsVSgx`　试过的地址:
  /files/…/download 200；/files/…/file-jNgKsM6YtMBIHm5BSsVSgx 404；/files/…/raw 404；/files/…/content 404
```

**`/download` 返回 200——成功。**图片根本没取不到，是代码没接住。

## 二、为什么没接住

那段代码是这样判的：200 之后，只有 content-type 是

- `json` → 去读里面的 `download_url`
- 含 `image` 或 `octet-stream` → 存下来

**其它一律什么都不做**，然后继续去试下一个端点（`.lastIndex` 那些注定 404 的）。而镜像站的 `/download` 恰恰是"200 但不带 content-type（或带别的）"，于是每个图片都经历了：第一次 200（被扔掉）→ 后面三次 404 → 最终判定"没取到"。

## 三、这一版怎么改

| 原来 | 现在 |
| --- | --- |
| 只认 json / image / octet-stream | **200 就拿字节** |
| 扩展名依赖 content-type | 用**文件头魔数**判断：png / jpg / gif / webp / pdf / bmp |
| 判不出类型也照样保存 | 判不出类型的（多半是登录页或错误页）跳过，并记进"试过的地址"，不硬塞 `.bin` |
| 日志只有状态码 | 状态码 + content-type（或"无 content-type"），方便继续排查 |

## 四、预期结果

这 6 张图（以及所有同样情况的图片）应该都能下到 `images/`，正文里就地显示成 `![图片](images/file-xxxx.png)`，VS Code 预览直接能看到。
