# 使用说明 v3.42（图片为什么"以前行、现在不行"，以及修法）

脚本文件：[src/aizex_export_v342.js](../src/aizex_export_v342.js)

## 一、"之前很成功、虽然是在文末" —— 那句话提醒了我

以前图片能显示，靠的是**把页面上渲染出来的图片地址整片捞下来**（那是浏览器正在用的地址，能直接下载），然后统一列在文末。

后来我在 v3.36 加了"界面图标过滤"，其中一条规则是：

> 位于 `button` / `role="button"` 里的图 → 当成界面图标跳过

而**面板恰恰把上传的图片包在"点开看大图"的按钮里**。于是：过滤界面 logo 的同一条规则，把对话里的真图也一起挡掉了——页面上渲染的地址没了，只剩下取不到文件流的那个指针，正文里就变成"图片未取到"。

一句话：**我自己的过滤器把真图过滤掉了。**

## 二、这一版的修法

判断"是不是界面图"要分场合：

| 场合 | 规则 |
| --- | --- |
| **消息里**的图 | 视为内容。只挡 16~24px 的小图标、以及名字里带 `logo`/`icon`/`emoji`/`avatar` 的 |
| **消息外**的图（侧边栏、工具栏） | 才按按钮 / 尺寸 / 关键词过滤（那才是界面装饰） |

实测过的三种情形都覆盖：消息里包在按钮里的大图 → 保留；消息里 16px 的图标 → 过滤；消息外 96px 的侧边栏 Logo → 过滤。

## 三、"可在面板里查看"这句话改掉了

原来那句确实含糊。现在直接写：

```
［图片未取到］`file-jNgKsM6YtMBIHm5BSsVSgx`
```

并且在文末附录里列出**试过的地址和状态码**，例如：

```
- ［图片未取到］`file-xxxx`　试过的地址: /files/…/download 404；/files/… 403；页面地址 200
```

文件头也会写 `> 附件: 4 个（已就地标在对应消息里）；其中 2 个没取到，原因见文末附录`。这样下次真失败，我一眼就能看出该加哪个端点，不用再猜。

## 四、格式标记仍是 md-v11

和上一版（接口断链修复）共用一次重导。你手上那批是 md-v10，重跑一趟会一起覆盖：长会话取全 + 图片能下 + 说明清楚。
