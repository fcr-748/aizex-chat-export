# 使用说明 v3.38（不再漏点展开；抓残的文件会自动重抓）

脚本文件：[src/aizex_export_v338.js](../src/aizex_export_v338.js)

这一版修的是最严重的一类问题：整条会话没点展开，前半段被掐断（实测《大学生失业讨论总结》开头就少了几轮）。

## 一、为什么会漏点展开

代码里有一条"快路径"：接口条数够多 + 打开会话时没看到折叠块，就只做一次快照、不展开。

听起来合理，但**折叠块是延迟渲染的**：打开会话的那一瞬间它还没出现，脚本据此判断"没有折叠"，于是**一次都没点**就走了。

现在改成：

- 打开后先等一拍（1.2 秒）再看
- 只有"页面上没有折叠块"**并且**"面板自己也没标共 N 轮"**并且**接口条数确实够多（≥40）才走快路径
- 只要面板标了折叠轮数，就老老实实展开

## 二、就算点了，之前也慢到跑不完

展开循环里每轮都对整页调 `innerText`，而 `innerText` 会强制重排——几百轮的会话上一次点击要几十秒，最后撞上 300 秒的时间预算被截断。

两处改掉：

- 热路径换成 `textContent`（不触发排版）
- 时间预算按面板标的轮数放大：`60 + 轮数 × 8` 秒，上限 15 分钟；普通会话仍是原来的预算

## 三、抓残的文件不再冒充"已抓全"

文件头以前不管抓全没抓全都写 `抓取机制: new`，而断点续跑正是靠这个标记跳过的——**一旦抓残就被永久跳过**。

现在没抓全会写：

```
> 抓取机制: partial
> 完整度: 未抓全（面板标 7 轮，实际只抓到 6 条），下次运行会重抓
```

下次运行会重新抓它，直到抓全为止。

## 四、页面版补来的"更早的消息"补到开头

接口那份缺了最早几轮时，只能靠页面版（展开折叠后）补。以前一律塞到文末附录，读起来就像被掐断。现在按位置合并：

| 位置 | 处理 |
| --- | --- |
| 排在正文之前 | 写到开头 `## 补：更早的消息（页面版，接口没返回）` |
| 排在正文之后 | 接到正文后面 |
| 位置对不上 | 才进文末附录 |

## 五、格式标记升到 md-v9

这条 bug 可能让一部分会话当初就抓残了（而且写着 `new` 被跳过），所以升一版标记**强制重抓一次**，把残的补回来。

你现在正在跑的那次是 md-v8，会被这趟重写。建议：重新加载扩展 → 用 v3.38 重跑。
